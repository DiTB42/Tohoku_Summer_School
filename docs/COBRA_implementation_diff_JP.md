## 1. ドキュメントと一致している部分（✅）

### 1.1 CPGの数式（§2） — 忠実
[`cpg/snake_cpg.py`](../cpg/snake_cpg.py) は式(9)〜(11)をほぼそのまま実装しています。

- **位相ダイナミクス** `φ̇ = ω + A·φ + B·θ` → [snake_cpg.py:64](../cpg/snake_cpg.py#L64)
- **振幅ダイナミクス（2階・臨界減衰）** `r̈ = a·[a/4·(R−r) − ṙ]` → [snake_cpg.py:67-72](../cpg/snake_cpg.py#L67-L72)（オイラー積分）
- **出力** `x = r·sin(φ) + δ` → [snake_cpg.py:75](../cpg/snake_cpg.py#L75)
- **結合行列 A**（三重対角・行和ゼロ＝グラフ・ラプラシアン、両端 −μ／内部 −2μ）→ [snake_cpg.py:31-42](../cpg/snake_cpg.py#L31-L42)。手計算で検証すると、対角が `[−μ, −2μ, …, −2μ, −μ]`・非対角が `μ`・各行和ゼロとなり、ドキュメント §2.3(a) の定義と一致します。
- **結合行列 B**（$n\times(n-1)$、`(Bθ)_1=θ_1`, `(Bθ)_i=θ_i−θ_{i-1}`, `(Bθ)_n=−θ_{n-1}`）→ [snake_cpg.py:44-50](../cpg/snake_cpg.py#L44-L50)。ドキュメント §2.3(a) と一致。
- **位相差 θ は単一値の複製**（ドキュメント §2.3 / 論文 IV.D.3「single value」）→ [snake_cpg.py:52-55](../cpg/snake_cpg.py#L52-L55) `np.full(n-1, phase_shift)`。以前の `(i+1)*θ` 増加列バグ（AUDIT項目9）は修正済み。

## 2. 大きな乖離（⚠️）

### 2.1 行動空間: $\mathbb{R}^4$（ドキュメント）→ スカラー θ のみ（実装） 🎓 学生課題

> **この差分は意図的に残しています（学生課題1）。** θのみの動く実装を保持したまま、拡張ポイントに
> `# TODO(学生課題1 …)` を置いています（[env_snake.py `action_space`](../env_snake.py#L36) と
> [`step()` の `theta = action`](../env_snake.py#L208) 付近）。実装手順は [`STUDENT_TASKS_JP.md`](STUDENT_TASKS_JP.md) 課題1 を参照。

**ドキュメント §3** は行動空間を $\mathbb{R}^4$ と規定:
- 振幅 $R \in [0, 1.5]$
- 周波数 $\omega \in [-0.1, 0.1]$
- 位相差 $\theta \in [-\pi, \pi]$
- オフセット $\delta \in [-0.1, 0.1]$
- → Actor 出力は tanh(4)

**実装**は行動を**スカラー1次元（θのみ）**に縮小:
- [env_snake.py:36-40](../env_snake.py#L36-L40): `action_space = Box(low=[0.5], high=[1.0])` → 1次元
- [env_snake.py:208-209](../env_snake.py#L208-L209): `theta = action` のみを CPG に渡し、`R, ω, δ` は固定値（[env_snake.py:26-28](../env_snake.py#L26-L28), `config.cpg.base_amplitude=1.0` / `base_omega=1.0` / `base_delta=0.0`）

これは README の実験表（Exp3「Reduced: θ only が最良」）に沿った**意図的な簡略化**です。ただしドキュメント §3 の設計とは以下の点で食い違います:

1. **次元**: 4 → 1。
2. **θの範囲**: ドキュメントは $[-\pi, \pi]$、実装は **[0.5, 1.0]**（[config/default.yaml:49-50](../config/default.yaml#L49-L50)）。波長を狭い正の範囲に限定。
3. **ωの値**: ドキュメントは $\omega \in [-0.1, 0.1]$ の小さな値を想定しているのに対し、実装は **ω=1.0 固定**（CPGクラスの既定値 `0.05`（[snake_cpg.py:19](../cpg/snake_cpg.py#L19)）も `set_parameters` で 1.0 に上書き）。ドキュメント想定より10〜20倍大きい周波数。
4. **δが 0 固定で旋回機構が無効**: ドキュメント §2.1 は「オフセット $\delta$ で体を弓なりにして**旋回**する」と説明しますが、実装は δ=0 固定のため、この旋回機構が使えません。学習パラメータ θ（波長）だけで挙動が決まり、能動的な操舵手段が乏しい構成です。corridor（ほぼ直線）タスクだから成立している面があります。

### 2.2 観測空間: 平面 ego-centric（ドキュメント）→ world座標寄り34次元（実装）

> **この差分は今回の実習では未対応のまま残しています（許容差分）。** 学生課題としては選定していませんが、
> 余力のある学生の発展課題になり得ます（§6 の推奨アクション1 を参照）。

**ドキュメント §3** の提案（平面運動向けの削減・**全て ego-centric**）:
- 関節角 $\mathbb{R}^n$
- IMU $\mathbb{R}^{2\text{〜}3}$
- ロボット座標系から見たウェイポイントの**相対位置** $\mathbb{R}^2$
- ロボット座標系から見たウェイポイントの**相対方位**（$\sin\psi, \cos\psi$）$\mathbb{R}^2$
- ※世界座標の絶対位置は入れない（ego-centric 設計思想）

**実装** [env_snake.py:182-202](../env_snake.py#L182-L202) の34次元:
- 関節位置 (12) + 関節速度 (12)
- `head_to_target_vec` (3): `current_target − head_pos`
- `head_orientation` axis-angle (4)
- `head_angular_vel` (3)

差分:
1. **平面削減されていない**: 3次元ベクトル＋ axis-angle(4) と、ドキュメントの平面版（2次元・sin/cos）ではなく、**原論文の21次元寄り**の構成。
2. **ego-centric（ロボット座標系）になっていない**: `head_to_target_vec` は**world座標系での差ベクトル**であり、ヘッドの回転で回していない（[env_snake.py:186-187](../env_snake.py#L186-L187)）。同様に `head_orientation` は**world系での絶対姿勢**（[env_snake.py:165-176](../env_snake.py#L165-L176)）。ドキュメントが強調する「ロボット座標系から見た相対量／絶対位置は入れない」という ego-centric 原則から外れています。
3. **相対方位（$\sin\psi,\cos\psi$）が観測に無い**: ドキュメントは目標への相対方位を観測に入れることを推奨。実装では観測にも報酬にもこの相対方位は入っていません（以前は報酬側に `cos(angle_to_target)` の向き整合項がありましたが、論文式(12)に無いため §2.4 で削除しました）。方策が方位情報を直接扱えない構図です。
4. **関節速度(12)を追加**: ドキュメントの提案リストには無い項目。

### 2.3 RLアルゴリズム: DDPG（ドキュメント）→ SAC（実装）

**ドキュメント §4.3** は RL アルゴリズムを **DDPG** と明記。
**実装**は **SAC**（Stable-Baselines3）を使用（[train_sac.py:53](../train_sac.py#L53)）。README の「System Overview / Technical Details」でも SAC と明記されており、意図的な変更です。ドキュメント側は元論文（DDPG）の記述をそのまま踏襲しているため、この点で食い違います。

### 2.4 報酬関数: 式(12)の3項に還元済み 🎓 重み設計は学生課題

**ドキュメント §4.2 / 式(12)** の報酬は3項:
- $r_1 = 1/(0.1 + d_t)$（近接）
- $r_2 = d_{t-1} - d_t$（接近速度）
- $r_3 = \|a_t - a_{t-1}\|$（行動変化ペナルティ）
- 総報酬は $w_1 r_1 + w_2 r_2 - w_3 r_3$ の形（重みは論文に無く実習で設計）

**現行実装**は式(12)の3項**のみ**になっています（[env_snake.py `step()`](../env_snake.py#L262)）:

```python
reward = (
    reward_cfg.w_progress * r1      # r1: 近接
    + reward_cfg.w_velocity * r2    # r2: 接近速度
    - reward_cfg.w_smoothness * r3  # r3: 行動変化ペナルティ（減算）
)
```

以前この実装には、論文式(12)に無い多数の追加項（`waypoint_bonus` / `goal_reward` / `control_penalty` /
`w_heading * cos(angle_to_target)` / `self_collision_penalty` / `tail_proximity_penalty` / `wall_penalty`）が
乗っていましたが、**論文の報酬に一致させるため全て削除**しました（§6 参照）。あわせて、旧実装の
`r3 = -0.3 * ||Δa||` というハードコード係数（二重係数）も除去し、`r3 = ||Δa||` として
`w_smoothness` で**減算**する論文どおりの符号・形に統一しています。

補足:
- ウェイポイントの **index 前進ロジック**と**ゴール到達によるエピソード終了 (`terminated`)** は、
  ナビゲーションに必須なため**制御フローとしては残置**しています（報酬への寄与だけを削除）。
  したがって論文どおり「ゴール到達に明示的なボーナスは無く、`r1` の近接報酬がゴール誘導を担う」構成です。
- **重み係数 $w_1, w_2, w_3$（`w_progress` / `w_velocity` / `w_smoothness`）は論文に記載がなく、
  学生が設計・調整する課題**として残しています（[`STUDENT_TASKS_JP.md`](STUDENT_TASKS_JP.md) 課題2、
  [config/default.yaml](../config/default.yaml#L6) の `reward` セクション）。この3重みの設計以外、報酬の項構成は論文式(12)と一致しています。

### 2.5 迷路生成: Kruskal・full maze（ドキュメント）→ 再帰バックトラッカー・corridor限定（実装）

**ドキュメント §4.1** は「**Kruskal法**でランダム迷路生成」「学習時にランダム化してゼロショット転移」を掲げます。

**実装**:
- 生成アルゴリズムは **再帰バックトラッカー（DFS）** `_carve`（[make_maze.py:9-29](../mazes/make_maze.py#L9-L29)）で、Kruskal法ではありません。
- 迷路サイズが **`height=3`**（[config/default.yaml:47](../config/default.yaml#L47)）。再帰バックトラッカーは2マス単位で掘り進むため、`height=3` では縦方向の分岐が原理的に生成されず、実質**1本道（corridor）**になります。README「Limitations」でも full maze は NaN で失敗すると明記されており、意図的にcorridor限定で運用されています。
- したがってドキュメント §1・§4.1 が謳う「ランダム迷路への**ゼロショット転移**」は、現状の設定では検証対象外です。

### 2.6 周波数比: 1:100（ドキュメント）→ 実効 1:500（実装）

**ドキュメント §4.3** は RL 0.5Hz : CPG 50Hz = **1:100** を規定。

**実装**の設定と実効値:
- [config/default.yaml:44-45](../config/default.yaml#L44-L45): `cpg_frequency=50`, `rl_frequency=0.1`
- [env_snake.py:24](../env_snake.py#L24): `sim_steps_per_rl_step = int(50/0.1) = 500` → 1回の行動を **500物理ステップ保持**
- 物理タイムステップは XML未指定のため MuJoCo既定 **0.002s**（`scene.xml`/`snake.xml` に `<option timestep>` 無し）。よって1行動あたり `500 × 0.002 = 1.0秒`。
- CPGの dt は `model.opt.timestep`（=0.002s、[env_snake.py:112](../env_snake.py#L112)）なので、**CPGは実際には約500Hzで更新**されます。

結果:
1. **RL:CPG比が 1:500**（ドキュメントの1:100と異なる）。
2. **`cpg_frequency=50` は名目値**で、実際のCPG更新レート（≒500Hz）とは一致していません。この「50Hz」ラベルは `sim_steps_per_rl_step` の分子として使われているだけです。
3. RLの意思決定周期は約 **1Hz**（ドキュメントは0.5Hz）。

> なお、CPG dt を `model.opt.timestep` に合わせた点自体は、AUDIT項目2（dt 10倍ずれ）の修正として妥当です。ただしドキュメントの「50Hz / 0.5Hz / 1:100」という数値とは整合していません。

## 3. 軽微な差分・実装上の注意（ℹ️）

### 3.1 位相の mod 正規化が未実装（§2.3 Tips）
ドキュメント §2.3 の実装Tipsは「φは $2\pi$ で mod を取り、結合項の差分は `arctan2(sin, cos)` で $[-\pi,\pi)$ に正規化せよ」と注意しています。実装は **mod を取らず** φ を単調増加させたまま結合項を計算しています（[snake_cpg.py:64,70](../cpg/snake_cpg.py#L64-L70)）。ラップアラウンドが無いため当面の破綻は起きませんが、長時間エピソードで φ が大きくなると浮動小数点精度の観点で不利。ドキュメントの推奨実装とは異なります。

### 3.2 ウェイポイント到達判定と報酬用ターゲットの分離
実装は、報酬シェーピング（r1, r2）には「現在WPと次WPの**中点**（lookahead）」を使い（[env_snake.py:155-164](../env_snake.py#L155-L164)）、到達判定には「WPの実座標」を使う（[env_snake.py:234-249](../env_snake.py#L234-L249)）という2系統を持ちます。これはAUDIT項目6の修正結果で妥当ですが、この「中点lookahead」という工夫はドキュメントには記載がない実装独自の要素です。

### 3.3 ウェイポイント配置がグリッドセル単位
ドキュメント §4.1 は「隣接ウェイポイント間距離が一定範囲に収まるよう配置」としますが、実装はA*が返した**格子セルをそのままウェイポイント**にしています（1セル=world換算1m間隔、[env_snake.py:97](../env_snake.py#L97)）。等間隔ではありますが「距離制約に基づく再配置」ではありません。

### 3.4 PIDゲイン
positionアクチュエータの `kp=0.1` は低め、`kv` 未指定。ドキュメント §4.5・§5-3 が言う「kp, kv のチューニングが必要」「まずCPG手動固定で直進・旋回を確認」という段階のチューニング余地が残っています。

## 4. 「意図的な簡略化」として許容される差分（README準拠）

以下はドキュメントと食い違うものの、README に明記された意図的な設計選択であり、「ドキュメント通りに直すべきバグ」ではありません（AUDIT_REPORT の [KEEP] と同趣旨）。

- **SAC採用**（DDPGでなく）（§2.3）— README明記。
- **corridor限定（`height=3`）**（§2.5）— README「Limitations / Future Work」に明記。full maze対応時にまとめて見直す想定。
- **車輪付き平面ヘビ（単一CPG）** という COBRA（pitch/yaw 2CPG・sidewinding）とは別のハードウェアモデル — ドキュメント §3 自身も「yaw軸のみへの読み替え」を前提にしており、方向性としては整合。
- **周波数比 1:500・観測の非 ego-centric・ネットワーク既定・学習規模の縮小**（§2.2, §2.6, §2.7, §2.8）— 短時間の実習で反復しやすくするための未対応の許容差分。§6 の発展課題。

> **学生課題として残置している差分**（§2.1 の #6 行動空間 θ→R⁴、§2.4 の #9 報酬の重み設計）は、上の「許容差分」とは区別されます。これらは**学生が実装して論文に一致させることを期待している未完成部分**であり、[`STUDENT_TASKS_JP.md`](STUDENT_TASKS_JP.md) に課題として明記しています。なお #6 の θ のみ縮小は README Exp3 では「最良」とされていますが、本実習では論文 §3 の $\mathbb{R}^4$ へ拡張する課題として位置づけています。

## 6. 推奨アクション（ドキュメントに寄せる場合の優先順）

> **学生課題（[`STUDENT_TASKS_JP.md`](STUDENT_TASKS_JP.md)）として割り当て済みなのは下記の 2（行動空間 R⁴ 化）と、§2.4 の報酬の重み設計です。** 1・3・4・5 は未対応の許容差分で、余力のある学生の発展課題になり得ます。

ドキュメント §3・§4 の設計に実装を近づけたい場合の着手順の目安:

1. **観測の ego-centric 化**（§2.2）: `head_to_target_vec` をヘッド回転行列で robot 座標系に回し、目標相対方位を $(\sin\psi,\cos\psi)$ で観測に追加する。ヘビの向きと目標方位の関係を方策が直接観測できるようになり、学習が安定しやすくなる（AUDIT項目10の延長）。
2. **行動空間の拡張**（§2.1）🎓 **学生課題1**: まず δ を行動に加えて**旋回機構を有効化**（corridor脱出・full maze対応の前提）。次いで R, ω を段階的に開放し $\mathbb{R}^4$ へ。θの範囲も $[-\pi,\pi]$ 側へ広げる。
3. **周波数・命名の整理**（§2.6）: `cpg_frequency` の名目値と実CPG更新レート（=1/`model.opt.timestep`）の不一致を解消し、RL:CPG比を明示的に管理する。必要なら物理 `timestep` を XML に明記。
4. **迷路生成の拡張**（§2.5）: `height` を5以上の奇数にし（縦通路が生成可能になる）、必要ならKruskal法に差し替え。full maze でのNaN再現・対策とセットで。
5. **ネットワーク/学習規模**（§2.7, §2.8）: `net_arch=[512,256,128]` 等をドキュメントに合わせる、`total_timesteps` を実運用規模へ。
